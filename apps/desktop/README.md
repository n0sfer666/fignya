# @fignya/desktop

Electron-оболочка. Импорт `.fig` идёт в отдельном процессе (`importer/`, `utilityProcess`), там же
живёт документ; main держит список страниц, renderer показывает страницы, миниатюры и живой DOM экрана.

## Команды (Nushell, из корня репо)

```nu
bun install
$env.FIG_FILE = ("~/Downloads/ROI Navigator.fig" | path expand)
bun run dev
```

- `bun run --cwd apps/desktop build` — прод-сборка в `apps/desktop/out/`.
- `bun run --cwd apps/desktop start` — запуск собранного (`FIG_FILE` так же).
- Кэш миниатюр: `~/Library/Application Support/fignya/thumbs/<cacheKey>/`, ключ — путь + размер +
  mtime `.fig` + `RENDER_HASH` (sha1 исходников model, fig-import, render-dom и `thumb.ts`; в dev
  считается при старте). Базовая миниатюра — `<id>.png` (0.5×), резкие уровни — `<id>@1x.png`,
  `<id>@2x.png` (сторона ≤ 4096). mtime каталога двигают открытие документа и запись новых PNG
  (чтение из кэша — нет). При открытии документа каталог с другим ключом удаляется, только если не
  открывался и не дописывался дольше 7 дней или не входит в 8 самых свежих (вместе со своим), —
  значит, рядом держатся и устаревшие версии того же файла (другой mtime `.fig`, в dev — каждая
  правка исходников рендера): до 8 каталогов, страница ROI Navigator на 199 экранов без резких
  уровней — ~11 МБ. Удалить папку — миниатюры перегенерируются.

## Runbook (T3, живое окно)

1. Запуск с `FIG_FILE`. Окно ~13 с показывает «Importing FIG_FILE… N%» и прогресс-бар: он
   растёт до 50% за декодирование и до 100% за конвертацию (первые ~0.5 с — 0%, идёт распаковка).
   Колёсика macOS нет: окно двигается и ресайзится, курсор обычный. В Activity Monitor процесс
   `fignya importer` держит до ~1.9 ГБ, основной процесс Electron — ~150 МБ. В терминале:
   `fignya: imported 9 pages, 406 screens in ~11000–14500 ms` (для ROI Navigator; верх — Low Power Mode),
   затем через ~11 с фонового дорезолва оверрайдов (экраны открываются и во время него)
   `fignya: settled 333207 overrides (0 instances failed) in ~11000 ms`; после него `fignya importer` падает до ~1.2 ГБ.
2. После импорта: тёмный UI, слева **Pages** (без `Internal Only Canvas`, справа от имени — число
   экранов) и **Screens** текущей страницы; холст вписывает первую страницу.
3. Миниатюры подгружаются лениво за секунды (сначала белые плашки). Повторный запуск берёт их из
   кэша мгновенно. Так же и при двух экземплярах с разными файлами: во втором терминале
   `cp $env.FIG_FILE /tmp/copy.fig; $env.FIG_FILE = "/tmp/copy.fig"; bun run --cwd apps/desktop dev`,
   в обоих окнах открыть одну и ту же страницу, дождаться миниатюр, закрыть оба, снова запустить
   любой — миниатюры сразу из кэша. Проверка:
   `ls ("~/Library/Application Support/fignya/thumbs" | path expand) | sort-by modified -r | first 2`
   — два каталога обоих файлов, в каждом PNG по числу экранов страницы. Сбой отрисовки или захвата (`UnknownVizError`, таймаут) повторяется: в логе
   `fignya: thumbnail <id> failed, retrying: …`, после чего миниатюра всё равно появляется; белыми
   не остаётся ни одна. Холодный кэш: закрыть приложение,
   `rm -r ("~/Library/Application Support/fignya/thumbs" | path expand)`, запустить снова. Зависший в
   окне миниатюр `img.decode()` через 0.5 с вызывается повторно и миниатюру не задерживает: на
   холодном кэше страница ROI Navigator на 199 экранов (на ней зависание ловится почти в каждом
   прогоне, на `14027:72673`) догружается за ~17 с, в логе нет `timed out`. Если повиснет и
   повторный — `thumbnail render timed out after 3000 ms`, ретрай в новом окне с запасом 15 с.
   Холодная страница ROI Navigator на 135 экранов догружается за ~10 с. Дефект (сообщить): строка
   `fignya: fignya://thumb/…: Error: thumbnail render timed out after 15000 ms` без `retrying` —
   упали обе попытки, плашка остаётся белой. Первая страница ROI Navigator пустая (0 экранов) —
   миниатюры пойдут после выбора страницы с экранами.
   Зум: через ~0.2 с после остановки видимые миниатюры подменяются резкими (`zoom × DPR` > 0.5 →
   уровень 1×, > 1 → 2×), без мигания; в кэше появляются файлы `@1x`/`@2x`. Через ~1–2 с после
   остановки зума все видимые экраны резкие (зависший `img.decode()` ждётся не дольше 1 с после
   загрузки файла). Дефект (сообщить) — экран остаётся мыльным, хотя его `@1x`/`@2x` уже в кэше. На retina при зуме
   100% текст миниатюр читается без клика, низ экрана не обрезан белым: файлы `@1x`/`@2x` из
   кэша заполнены до низа, в том числе у высокого экрана с дробным масштабом. Экраны вне окна и все экраны при отдалении
   возвращаются к базовой миниатюре. Базовые миниатюры рендерятся раньше резких. Высокий экран,
   упёршийся в 4096, не плодит одинаковых уровней (1440×4096 → максимум `@1x`).
4. Pan — скролл трекпада или drag. Zoom — pinch или ⌘/Ctrl + колесо, вокруг курсора.
5. Клик по экрану на холсте или в списке Screens (из списка — ещё и центрирование): миниатюра
   заменяется живым DOM с синей обводкой — фреймы, auto layout как flex, текст, rect/ellipse,
   картинки, векторы (SVG), инстансы (дерево компонента с оверрайдами). Esc закрывает живой DOM.
6. Оверрайды инстансов: открыть 3–4 экрана с кнопками, карточками, табами, иконками и сверить с Figma.
   Совпадают: тексты в инстансах (не текст компонента по умолчанию), шрифт и размер текста,
   показанные/скрытые слои (bool-свойства: иконки слева/справа, бейджи), свопнутые иконки и вложенные
   компоненты, цвет заливки/обводки и радиусы, размеры и позиции детей инстанса. Подписи кнопок,
   табов и фильтров — реальные значения (не «Content»/«Key»); auto-width тексты в одну строку,
   обрезанные — с «…» (многострочные и старые однострочные — по целым словам, новые однострочные —
   посимвольно, как в Figma); радиусы и отступы из числовых переменных (сегмент-контролы скруглены
   по краям); сегменты с отрицательным отступом внахлёст, разделители между ними видны;
   вкладки без «жирного» размытия; вкладки подчёркнуты снизу, а не обведены; экран не сдвинут влево, fill-колонки
   делят свободное место. Экран `15633:62993` совпадает с Figma целиком: заголовки капсом из
   текстовых стилей, цвета и иконки по переменным и стилям заливки/обводки, тени
   карточек и иконок, отражённые стрелки, сетка карточек с межстрочным отступом, подписи оси
   равномерно по ширине (space-between), кольцевые диаграммы дугами, легенды. Дети компонента в
   инстансе берут режим переменных по месту инстанса: на экране `2479:26710` вкладки
   светлые (белая заливка, тёмная обводка снизу), а не тёмно-серые, как компонент на тёмном листе;
   так же цвета внутри инстансов на `9402:158329` и `5873:93717`. Dark-фреймы экранов с локальными
   наборами переменных библиотечные цвета не меняют — массовой тёмной темы там не будет. Повёрнутые
   дети auto layout повёрнуты и занимают в ряду бокс поворота: на `14999:110842` подпись оси Y
   вертикальная слева от делений, вертикальная сетка
   равномерно по ширине графика и стоит под подписями оси X; на `14026:73182` разделители карточек и
   сетка графиков вертикальные, сетка нижнего графика — под подписями времени. Не ждать:
   тексты с частичным стилем (рисуются одним стилем); точные ширины и переносы текстов без
   установленных Manrope/Inter (`brew install --cask font-manrope font-inter`).
7. Смена страницы в Pages заново вписывает холст. Переключение, пока миниатюры старой страницы ещё
   рендерятся (холодный кэш: открыть страницу на 199 экранов и сразу перейти на соседнюю на 135),
   не ждёт хвоста старой: первая миниатюра новой страницы — за ~0.3 с, в кэш после переключения
   попадает не больше одной миниатюры старой (та, что уже рисовалась). Возврат на старую страницу
   догружает все её миниатюры, белых не остаётся.
8. Шрифты документа. Холодный кэш: закрыть приложение,
   `mv ("~/Library/Application Support/fignya/fonts" | path expand) /tmp/fignya-fonts`. Через ~10–20 с
   после `ready` (после `settled`) в сайдбаре между Pages и Screens — секция **Fonts**: семейства,
   которых нет ни в системе, ни в кэше, с числом текстовых узлов и статусом `missing` (для ROI Navigator
   без установленных шрифтов: YS Text 2062, Roboto 526, Rubik 311, Geist 93, Urbanist 34, IBM Plex Mono 5,
   Outfit 3, IBM Plex Sans 2). Установленные в системе семейства (Manrope, Inter) в списке не появляются.
   Кнопка **Download from Google Fonts** → «Downloading…» → за ~1–3 с статусы `downloaded` (зелёный),
   YS Text — `not on Google Fonts`; кнопка исчезает. Без сети — `download failed` и кнопка остаётся.
   В той же сессии миниатюры холста перерисовываются: на `47:3439` (страница на 25 экранов) подписи
   строк таблицы жирные (Rubik), короткая вкладка сегмент-контрола без многоточия; на `89:2590` (Roboto)
   число с единицей в заголовке карточки в одну строку. Открытый живой экран берёт шрифт сразу. В каталоге `fonts/` — `faces.json` и
   `woff2` (86 файлов для ROI Navigator), в `thumbs/` — новый каталог миниатюр. Повторный запуск:
   шрифты из кэша без сети, в Fonts только YS Text `missing` (недоступное в Google Fonts не
   запоминается), миниатюры сразу с новыми шрифтами.
9. Закрытие окна завершает приложение.

Без `FIG_FILE` — красная надпись `FIG_FILE is not set`. `FIG_FILE` не `.fig` (например,
`package.json`) — красная `invalid zip data`, процесс `fignya importer` из Activity Monitor исчезает.

## Замер импорта без Electron

```nu
$env.FIG_FILE = ("~/Downloads/ROI Navigator.fig" | path expand)
bun run --cwd packages/fig-import bench
```

Вывод — одна JSON-строка: `importMs`, `nodes`, `maxRssMb`, `heapAfterGcMb`. Для ROI Navigator:
`importMs` ~11000 (Low Power Mode), `nodes` 360637, `maxRssMb` 2600–3500 (плавает от давления памяти; Node без
pointer compression, в Electron меньше), `heapAfterGcMb` ~1090. Оверрайды инстансов в bench не
резолвятся (ленивые), поэтому куча держит поддеревья компонентов; после резолва всех инстансов — ~490.

Счётчики модели — `bun run --cwd packages/fig-import inspect` (тот же `FIG_FILE`): время сборки
`ScreenModel` первого открытия экрана `screenModelMs` p50 ~10, p99 ~110, max ~160 мс; для ROI Navigator
`overrides.total` 333207 (`style` 177039, `hidden` 48342, `text` 40377, `componentId` 20810, `paths` 134267;
пути — в основном масштабированные иконки инстансов и перекраски, шум округления ≤ 0.02 не считается).
