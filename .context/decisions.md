# Решения

## Раунд 1 (2026-09-23)

- Свой проект, не форк OpenPencil (у него canvas/Skia, DOM-бэкенд = переписать рендер).
- **Источник правды — модель документа, DOM — проекция.** Модель говорит на языке CSS
  (flex/grid/border-radius), перевод из Figma-терминов делает импорт один раз.
- Компоненты при импорте не расплющивать: инстанс = ссылка + оверрайды.
- Рендер **по экранам**: экран = top-level FRAME на CANVAS или внутри SECTION. Живой DOM только у
  открытого экрана, обзор страницы — растровые миниатюры.
- Страница `Internal Only Canvas` — служебная (компоненты), как экраны не рендерится.
- Пиксель-в-пиксель не цель; auto layout (88% контейнеров) → flexbox детерминированно.
- Prototype interactions → декларативная state machine + View Transitions.
- Базовые функции без ИИ и без сети. ИИ: MCP-сервер + OpenAI-compatible + Anthropic; встроенный
  llama.cpp — фаза 2, модель качается по согласию.
- Shell (Electron vs Tauri) — по цифрам спайка S1, не по мнению.
- Лицензия MIT, репо github.com/n0sfer666/fignya (публичный).
- Юр. сторону формата `.fig` пользователь проверяет сам. Сроки не блокер (разработка ИИ-агентами).

## S1 — shell (2026-09-24): **Electron**

Прогон REPS=3, M3 Pro 120 Гц, от сети, Low Power Mode выключен (`spikes/s1-dom-perf/results/2026-09-24T11-34-15.md`).

| | Electron | Tauri (WKWebView) |
|---|---|---|
| first frame, экраны 559–4054 DOM | 14–44 мс | 119–189 мс |
| pan/zoom, экраны | 120 fps, janky 0–2 | 60 fps (кап WebKit на 120 Гц), janky 0–1 |
| обзор 199 миниатюр, zoom без will-change | 118 fps, janky 1 | 39 fps, janky 34 |
| RSS, экраны | 360–560 МБ | 170–250 МБ |
| RSS, обзор | 450–620 МБ | 360–470 МБ |

- Живой DOM выдерживают оба: даже max-экран (4k элементов) без просадок.
- За Electron: в 3–8 раз быстрее первая отрисовка, 120 Гц, стабильный зум обзора; один движок
  на всех ОС (Tauri = WebKit/WebView2/WebKitGTK → дизайн рендерится по-разному — для
  HTML/CSS-редактора это дефект продукта); offscreen `capturePage` для миниатюр из коробки.
- Против: +200–300 МБ RSS. Принято: для дизайн-инструмента на 18 ГБ приемлемо.
- WKWebView под Low Power Mode режет rAF до 30 fps — ещё один аргумент против.
- Обзор держать с `will-change: transform` на слое мира (у Tauri без него zoom разваливается,
  Electron равнодушен).

## MVP

Импорт `.fig` → список страниц/экранов → живой HTML/CSS экрана (frame, auto layout→flex, text,
rect/ellipse, image fill, vector→SVG из cached geometry, instance→компонент), выделение,
инспектор, правка базовых свойств, click-interactions (navigate), экспорт HTML/CSS.
macOS (M3 Pro, 18 GB) в приоритете, кросс-платформенность не ломать.

## Backlog (не MVP)

- ИИ-вывод flex/grid из абсолютного позиционирования (12% контейнеров).
- Отчёт о подменах начертаний у установленных семейств (нет нужного веса/курсива) — отчёт о
  шрифтах показывает только недостающие семейства целиком.
- Фичи без CSS: squircle (`corner-shape`), diamond-градиент, outside/center stroke на
  произвольной форме, progressive blur, noise/glass, text on path.
- ИИ/MCP поверх Command API — кандидат раунда 6.
- Хвосты SWAP_STATE (раунд 5): фрейм-держатель ON_HOVER откатывается по уходу с целевого инстанса, а не с фрейма; после
  смены внешнего инстанса адреса вложенных держателей другие (повторный MOUSE_ENTER на том же месте); оверрайды
  stored-инстансов промежуточных уровней не переводятся; ON_PRESS, AFTER_TIMEOUT и прочие события.
- Хвосты сохранения (раунд 5): ручная проверка ⌘Q с несохранёнными правками (T3 подтвердил вопрос только при закрытии
  окна); `shared-node/`, если появится второй модуль вроде `write-atomic` (importer берёт его из `main/`).

## Раунд 4 (2026-10-13): выделение + инспектор

- Раунд 3 закрыт (T3 пройден), `feat/app-skeleton` уходит в `main` PR-ом (merge commit, история коммитов сохраняется).
- Первый срез — выделение и инспектор **только на чтение**; правка и Command API (где живёт изменяемый
  документ: importer / main / renderer) — следующим срезом.
- Клик как в Figma: верхний уровень внутри экрана, двойной клик — шаг вглубь, ⌘+клик — самый глубокий слой.
- Инспектор говорит на языке CSS модели (layout/flex, размеры, фон, обводка, типографика) + id/имя/тип,
  компонент инстанса.
- (2026-10-14) Esc: первый снимает выделение, второй закрывает живой экран. Инспектор показывает итоговые значения
  (оверрайды инстанса и подгонка под ресайз применены) CSS-декларациями по секциям; цель поиска ⌘F — обычное выделение.
- (2026-10-14, срез 2) Изменяемый документ живёт в **importer**: он уже держит `NodeMap`, поиск, миниатюры и повторное
  открытие экрана видят правку без копий. Renderer модели не держит, правку собирает из отрисованной ноды.
- Command API — в памяти, undo/redo по одной правке (лимит 200), на диск и в `.fig` ничего не пишется. Правка слоя внутри
  инстанса — оверрайд внешнего развёрнутого инстанса; правка мейн-компонента меняет все инстансы.
- Редактируемые поля: W/H, solid-заливка (заменяет все paint), opacity, gap/padding auto layout, corner radius, текст,
  font-size/weight. W/H внутри инстанса пишет весь бокс, иначе подгонка под ресайз выключится и слой сдвинется.
- ⌘Z/⌘⇧Z ловит renderer: вне полей ввода и в поле инспектора без непримененного набора (сразу после Enter) шлёт в main,
  в поле с набором и в поиске — `document.execCommand` (своё undo поля, роли `undo` в меню
  нет). Пункты меню Edit с `registerAccelerator: false`, иначе акселератор меню перехватит клавиши и в полях ввода. Буква Z
  берётся из `key`, `code` — запасной для нелатинских раскладок.
- Миниатюры: у экрана ревизия в памяти main, `r=` в URL сбрасывает кэш картинки браузера. После первой правки (любой, принятой
  importer, даже вне экранов) дисковый кэш миниатюр не пишется: правка мейн-компонента меняет и чужие экраны, а ключ кэша
  (файл + шрифты) правок не видит — иначе после перезапуска миниатюры показали бы несуществующую правку. Читают кэш только
  неправленые экраны (ревизия 0): иначе после правки каждая миниатюра рендерилась бы заново; цена — чужие экраны с
  инстансом правленого компонента до перезапуска со старой картинкой.
- После перерисовки живого экрана выделение — то, что у пользователя сейчас (по точному адресу правки), а не цель правки:
  клик по другому слою, пока правка в пути, не откатывается. Правка-пустышка (значение не меняется) в историю не идёт.
- Диапазоны значений правки — одно место, `isStylePatch` (`packages/model`): им проверяет и поле инспектора, и main ввод
  из renderer.
- (2026-10-14, срез 3) Экспорт — открытый живой экран (File → Export Screen…, ⌘E; без экрана пункт неактивен) в папку
  `index.html` + `styles.css` + `images/` + `fonts/`. CSS — классы `.nN` по одинаковым наборам деклараций, `data-id`/`data-kind`
  остаются. Шрифты: скачанные начертания (кэш Google Fonts) копируются, системные и проприетарные — только имя. Не входит:
  слой/страница целиком, семантические имена классов, адаптив.
- (2026-10-14, срез 4) Play — режим поверх окна (View → Play, ⌥⌘↩; без живого экрана неактивен) со старта на живом экране:
  только ON_CLICK → NAVIGATE на экран, мгновенно; экран по ширине окна (≤ 1), скролл по вертикали; клик мимо — подсветка
  хотспотов, ←/Backspace — назад по истории Play, Esc — холст как был. Рендер — тот же `renderScreen` в shadow root, а не
  `<iframe>`: шрифты и `fignya://` уже работают, скриптов нет. Связь — `link?: NodeId` у узла и оверрайда (первая ON_CLICK →
  NAVIGATE). Не входит: анимации переходов, overlay, SWAP_STATE (hover/click → вариант; 19,8k взаимодействий в ROI Navigator —
  главная доля прототипа, backlog), связи в экспорте.
- (2026-10-14) Раунд 4 закрыт: MVP (выделение, инспектор, правка, экспорт, Play) готов, T3 всех срезов пройден;
  `feat/selection-inspector` уходит в `main` PR-ом (merge commit). Направление раунда 5 — опросом
  (кандидаты: сохранение документа, SWAP_STATE в Play, ИИ/MCP).

  правки не применяются, предупреждение диалогом; первое ⌘S копирует старый sidecar в `.fignya.bak` и только потом
  атомарно пишет новый (упала запись — старый цел). `.bak` один и перезаписывается: держит последний вытесненный sidecar,
  более старые базы не храним (ревью раунда 5). Sidecar больше 64 МБ не читается (stale), лишние поля правок отбрасываются.
- File → Save (⌘S), точка несохранённого (`setDocumentEdited`), Save / Don't Save / Cancel при закрытии окна и ⌘Q.
  Без правок ⌘S ничего не пишет. Сохранённые правки после открытия в undo не попадают.
- Пишет importer (у него история и путь): правки после открытия и записи — `dirty` по сравнению итоговых правок с
  сохранёнными, отмена до сохранённого состояния — снова чисто. Ключ кэша миниатюр включает хэш восстановленных правок.
- План и статус — `notes/round5-save.md`.

## Раунд 5, срез 2 (2026-10-14): SWAP_STATE в Play

- Направление (опрос): SWAP_STATE — 19,8k взаимодействий в ROI Navigator, главная доля прототипа; ИИ/MCP — позже.
  Ветка `feat/swap-state` стеком от `feat/document-save` (PR #3 → `feat/selection-inspector`, PR #2 не смержен).
- События: ON_HOVER (уход курсора возвращает вариант, бывший до наведения), MOUSE_ENTER, MOUSE_LEAVE, ON_CLICK — 99,7% в ROI;
  ON_PRESS, AFTER_TIMEOUT и прочие не поддерживаются. Смена мгновенная. NAVIGATE на том же клике побеждает смену.
- Данные ROI: 17,6k SWAP_STATE на инстансах (копия из компонента) и 2k на корнях вариантов ведут в соседний вариант своего
  набора; 135 — на фреймах внутри варианта: меняется ближайший инстанс, чей вариант — сосед цели.
- Оверрайды и правки переносятся как в Figma — по цепочке имён слоёв от корня варианта (n-й среди тёзок), на уровне модели
  в renderer. У соседних вариантов `overrideKey` разные: без перевода в новом варианте не ложится ни один из 44k оверрайдов,
  по именам — 29,2k, ещё 14,9k — оверрайды корня. Глубже не ложатся там, где слой нового варианта привязан к другому пропу
  (данные файла). Стиль корня инстанса: ключи, равные корню старого варианта, берутся у нового (как `swap-rebase` в импорте);
  бокс (позиция, размер, свойства flex-ребёнка) — свой.
- При смене инстанс сохраняет свою связь (NAVIGATE), а смены берёт у нового варианта: иначе наведение стирает переход
  кнопки, и клик после hover никуда не ведёт.
- Откат ON_HOVER возвращает снимок внешнего инстанса до наведения (а не встречную смену): оверрайды слоёв, которых нет в
  hover-варианте, и свой стиль корня не теряются. Откаты — в обратном порядке; если внешний инстанс сменили позже
  (клик во время наведения), откат — встречной сменой к варианту до наведения.
- Вложенный инстанс после смены рисуется как свап из файла: содержимое не-flex варианта масштабируется к слоту; внешний —
  по констрейнтам, как инстанс этого варианта в файле.
- Смены берутся только у самого узла (импорт копирует взаимодействия варианта во все 17,6k его инстансов в ROI); фолбэк к
  компоненту воскрешал удалённые на инстансе. Клик-смена, которую некуда применить, — подсветка хотспотов, как клик мимо.
- Слияние `prototypeInteractions` оверрайда с базой — по `id`; пустой список или элементы без `id` заменяют список, actions
  другой длины — тоже замена. На ROI число смен и ссылок то же, что при прежней полной замене.
- Состояние живёт до ухода с экрана: переход и ← открывают экран как в файле; холст и живой экран вне Play не меняются.
- Перерисовка — поддерево внешнего инстанса (render-dom помнит контекст ветки), не весь экран.
- В модель экрана попадают варианты, достижимые сменами (замыкание), — одинаково для Play и живого экрана.
- План и статус — `notes/round5-swap-state.md`.

## Раунд 6 (2026-10-14): ИИ-агент через MCP

- Направление (опрос `/spec-interview`): MCP-сервер для внешнего агента поверх Command API, без своего LLM-рантайма и чата.
  Спека — `specs/2026-10-14-round6-mcp.md`.
- Транспорт — Streamable HTTP на 127.0.0.1 из main (официальный SDK); выключен по умолчанию, Bearer-токен, Host-проверка.
  Обязательный клиент — Claude Code.
- Агент видит конспект (инстансы свёрнуты) + PNG; значения стиля — CSS-строки; пачка = один шаг undo, всё или ничего;
  мейн-компонент — по флагу `affectsInstances`; undo агента — только своя пачка на вершине; save — только пользователь.
- Ключи расширяются видимостью и обводкой (в UI тоже); обводка — поле `stroke` модели (по умолчанию: вопрос пропущен).
- Нарезка: 6.1 MCP на текущих 12 ключах (отдельная сессия, схема правок из `EDIT_KEYS`), 6.2 видимость + обводка.
- 6.1 (сессия 26-10-14): SDK `@modelcontextprotocol/sdk` 1.31.0 + `zod` 4.6.5 (точные версии, в бандле main); порт 7341
  (`FIGNYA_MCP_PORT`; 3845 занят MCP Figma Desktop); PR стеком в `feat/swap-state`. Пачку разбирает main (CSS-строки →
  `Edit[]` через `parseAgentEdit`), importer проверяет её на документе целиком (`prepareBatch`: узел есть, `text` — только у текста,
  мейн-компонент — по `affectsInstances`, бокс достраивается) и применяет одним шагом истории `{ origin }`; лимиты — 200 правок от агента,
  1000 в протоколе importer. `nestedScope` переехал из render-dom в model (адрес разрешает importer), достройка бокса узла
  внутри инстанса — в model (`edit-box`). Поиск по подстроке имени — только у MCP (флаг `names`), ⌘F без изменений.
  `screenshot` узла — область экрана по боксу узла через `thumb-renderer.measure`. Индикатор агента — открытый
  SSE-поток или вызов за последние 120 с (Claude Code держит GET-поток не всегда). Сессий HTTP — до 8, лишняя вытесняет
  старейшую. `RENDER_HASH` сменился (thumb.ts) — кэш миниатюр перегенерируется один раз.
  По ревью: адрес — до 64 звеньев по 64 символа (`address-limits` в model, одни лимиты у MCP и guards importer);
