# Решения

## Раунд 1 (2026-09-23)

- Свой проект, не форк OpenPencil (у него canvas/Skia, DOM-бэкенд = переписать рендер).
- **Источник правды — модель документа, DOM — проекция.** Модель говорит на языке CSS
  (flex/grid/border-radius), перевод из Figma-терминов делает импорт один раз.
- Компоненты при импорте не расплющивать: инстанс = ссылка + оверрайды.
- Рендер **по экранам**: экран = top-level FRAME на CANVAS или внутри SECTION. Живой DOM только у
  открытого экрана, обзор страницы — растровые миниатюры.
- Страница `Internal Only Canvas` — служебная (компоненты), как экраны не рендерится.
- Пиксель-в-пиксель не цель; auto layout (88% контейнеров) → flexbox детерминированно.
- Prototype interactions → декларативная state machine + View Transitions.
- Базовые функции без ИИ и без сети. ИИ: MCP-сервер + OpenAI-compatible + Anthropic; встроенный
  llama.cpp — фаза 2, модель качается по согласию.
- Shell (Electron vs Tauri) — по цифрам спайка S1, не по мнению.
- Лицензия MIT, репо github.com/n0sfer666/fignya (публичный).
- Юр. сторону формата `.fig` пользователь проверяет сам. Сроки не блокер (разработка ИИ-агентами).

## S1 — shell (2026-09-24): **Electron**

Прогон REPS=3, M3 Pro 120 Гц, от сети, Low Power Mode выключен (`spikes/s1-dom-perf/results/2026-09-24T11-34-15.md`).

| | Electron | Tauri (WKWebView) |
|---|---|---|
| first frame, экраны 559–4054 DOM | 14–44 мс | 119–189 мс |
| pan/zoom, экраны | 120 fps, janky 0–2 | 60 fps (кап WebKit на 120 Гц), janky 0–1 |
| обзор 199 миниатюр, zoom без will-change | 118 fps, janky 1 | 39 fps, janky 34 |
| RSS, экраны | 360–560 МБ | 170–250 МБ |
| RSS, обзор | 450–620 МБ | 360–470 МБ |

- Живой DOM выдерживают оба: даже max-экран (4k элементов) без просадок.
- За Electron: в 3–8 раз быстрее первая отрисовка, 120 Гц, стабильный зум обзора; один движок
  на всех ОС (Tauri = WebKit/WebView2/WebKitGTK → дизайн рендерится по-разному — для
  HTML/CSS-редактора это дефект продукта); offscreen `capturePage` для миниатюр из коробки.
- Против: +200–300 МБ RSS. Принято: для дизайн-инструмента на 18 ГБ приемлемо.
- WKWebView под Low Power Mode режет rAF до 30 fps — ещё один аргумент против.
- Обзор держать с `will-change: transform` на слое мира (у Tauri без него zoom разваливается,
  Electron равнодушен).

## MVP

Импорт `.fig` → список страниц/экранов → живой HTML/CSS экрана (frame, auto layout→flex, text,
rect/ellipse, image fill, vector→SVG из cached geometry, instance→компонент), выделение,
инспектор, правка базовых свойств, click-interactions (navigate), экспорт HTML/CSS.
macOS (M3 Pro, 18 GB) в приоритете, кросс-платформенность не ломать.

## Backlog (не MVP)

- ИИ-вывод flex/grid из абсолютного позиционирования (12% контейнеров).
- Отчёт о подменах начертаний у установленных семейств (нет нужного веса/курсива) — отчёт о
  шрифтах показывает только недостающие семейства целиком.
- Фичи без CSS: squircle (`corner-shape`), diamond-градиент, outside/center stroke на
  произвольной форме, progressive blur, noise/glass, text on path.

## Раунд 3 (2026-09-24): каркас приложения

- Ядро (импорт, модель) пока на **TS**, пакетами с чистыми границами; перенос в Rust/napi-rs —
  когда упрёмся в перф или дойдём до Loro/ИИ. `stack.md` в части Core — цель, не текущее состояние.
- DoD раунда — **просмотрщик**: `FIG_FILE` → страницы/экраны → обзор миниатюрами (offscreen
  `capturePage`, `will-change: transform` на слое мира) с pan/zoom → клик открывает живой DOM экрана.
  Выделение, инспектор, правка — следующий раунд.
- Сборка: Bun workspaces + `electron-vite` + `vite-plugin-solid`, тесты Vitest (TDD на синтетических фикстурах).
- План и статус — `notes/round3-skeleton.md`.
- Шрифты документа (2026-10-02): отчёт о недостающих семействах — секция Fonts в сайдбаре после
  `settled`; загрузка из Google Fonts (css2 API, файлы только с `fonts.gstatic.com`, на практике woff2) только по кнопке, кэш
  `userData/fonts/` (`faces.json` + файлы), offline из кэша. Проприетарные (YS Text) — только
  системные. Ключ миниатюр включает версию набора шрифтов (глобальную: загрузка один раз
  инвалидирует миниатюры всех документов); холст перезапрашивает их в той же сессии.
  Начертания, на которые Google Fonts ответил 400, запоминаются в `fonts/unavailable.json` на 30 дней
  (`main/font-unavailable.ts`) — по начертанию, не по семейству: 400 на один вес не значит, что семейства
  нет. Хранятся отдельно от `faces.json`, иначе изменили бы версию набора и ключ миниатюр.

## Раунд 4 (2026-10-13): выделение + инспектор

- Раунд 3 закрыт (T3 пройден), `feat/app-skeleton` уходит в `main` PR-ом (merge commit, история коммитов сохраняется).
- Первый срез — выделение и инспектор **только на чтение**; правка и Command API (где живёт изменяемый
  документ: importer / main / renderer) — следующим срезом.
- Клик как в Figma: верхний уровень внутри экрана, двойной клик — шаг вглубь, ⌘+клик — самый глубокий слой.
- Инспектор говорит на языке CSS модели (layout/flex, размеры, фон, обводка, типографика) + id/имя/тип,
  компонент инстанса.
- (2026-10-14) Esc: первый снимает выделение, второй закрывает живой экран. Инспектор показывает итоговые значения
  (оверрайды инстанса и подгонка под ресайз применены) CSS-декларациями по секциям; цель поиска ⌘F — обычное выделение.
- (2026-10-14, срез 2) Изменяемый документ живёт в **importer**: он уже держит `NodeMap`, поиск, миниатюры и повторное
  открытие экрана видят правку без копий. Renderer модели не держит, правку собирает из отрисованной ноды.
- Command API — в памяти, undo/redo по одной правке (лимит 200), на диск и в `.fig` ничего не пишется. Правка слоя внутри
  инстанса — оверрайд внешнего развёрнутого инстанса; правка мейн-компонента меняет все инстансы.
- Редактируемые поля: W/H, solid-заливка (заменяет все paint), opacity, gap/padding auto layout, corner radius, текст,
  font-size/weight. W/H внутри инстанса пишет весь бокс, иначе подгонка под ресайз выключится и слой сдвинется.
- ⌘Z/⌘⇧Z ловит renderer: вне полей ввода и в поле инспектора без непримененного набора (сразу после Enter) шлёт в main,
  в поле с набором и в поиске — `document.execCommand` (своё undo поля, роли `undo` в меню
  нет). Пункты меню Edit с `registerAccelerator: false`, иначе акселератор меню перехватит клавиши и в полях ввода. Буква Z
  берётся из `key`, `code` — запасной для нелатинских раскладок.
- Миниатюры: у экрана ревизия в памяти main, `r=` в URL сбрасывает кэш картинки браузера. После первой правки (любой, принятой
  importer, даже вне экранов) дисковый кэш миниатюр не пишется: правка мейн-компонента меняет и чужие экраны, а ключ кэша
  (файл + шрифты) правок не видит — иначе после перезапуска миниатюры показали бы несуществующую правку. Читают кэш только
  неправленые экраны (ревизия 0): иначе после правки каждая миниатюра рендерилась бы заново; цена — чужие экраны с
  инстансом правленого компонента до перезапуска со старой картинкой.
- После перерисовки живого экрана выделение — то, что у пользователя сейчас (по точному адресу правки), а не цель правки:
  клик по другому слою, пока правка в пути, не откатывается. Правка-пустышка (значение не меняется) в историю не идёт.
- Диапазоны значений правки — одно место, `isStylePatch` (`packages/model`): им проверяет и поле инспектора, и main ввод
  из renderer.
